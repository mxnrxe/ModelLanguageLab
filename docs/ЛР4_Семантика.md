# Семантический анализ

`language/semantic.py` расширяет рекурсивный спуск из ЛР3 семантическими
действиями. Вход — готовые лексемы. При ошибке лексики или синтаксиса
семантика не проверяется. Проверка останавливается на первой ошибке.

- `dim` заполняет типы в TI: `%` — integer, `!` — real, `$` — boolean.
  Имена объявляются один раз и до использования; адреса не назначаются на ЛР4.
- `+`, `-`, `*` принимают числовые операнды. Результат integer для двух
  целых, иначе real. `/` всегда даёт real. Сравнения чисел дают boolean;
  для двух boolean также разрешено `=`. `!`, `or`, `and` требуют boolean.
- Присваивание требует совпадения типов, разрешено расширение integer → real.
  Условия if и while — boolean. Счётчик, начальное значение, граница и шаг
  for — integer. Ввод требует объявленного идентификатора, вывод — выражений
  допустимых типов.
- Стек хранит типы и знаки операций. После чтения правого операнда тройка
  заменяется типом результата из TOP. Тип числа определяется по виду
  конкретной лексемы, а не по общему значению в TN.

Вычисление значений, проверка инициализации и распределение памяти в ЛР4
не выполняются. Журнал показывает первые 3000 действий, проверка при этом
продолжается. Пример — `examples/semantic.txt`.

## Процедуры из методички

- `Dc` кладёт контрольный 0 в стек объявлений. При чтении каждого имени
  `instl` добавляет его номер TI. После чтения типа `dec` извлекает номера
  до нуля и вызывает `decid`. Группа записывается в TI после проверки всех
  имён; позиции лексем сохраняются для сообщения о повторе.
- `inst` и `outst` кладут и снимают элементы. `checkid` проверяет объявление
  и возвращает тип; `Mn` кладёт его в стек, если имя встречено в выражении.
- `checkop` снимает правый тип, знак, левый тип. `gettype` ищет запись в
  TOP; при успехе `checkop` кладёт тип результата обратно. `checknot`
  отдельно проверяет отрицание `!`.
- `eqtype` проверяет присваивание, `eqbool` — логический тип условия.

Имена `Dc`, `Id`, `Mn` и остальных функций разбора сохранены из грамматики ЛР3.
