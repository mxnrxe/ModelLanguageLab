# Соответствие грамматике ЛР1

Основание: формальная грамматика из `ЛР1_11.docx`.
SHA256 исходного документа: `a91f11fd6b58d0718f7b19355d5e0511fa0987a28dc2cfd5b9ddae11c6cdd3a8`.
Метод: рекурсивный спуск согласно методическим указаниям ЛР3.
Реализация: `language/parser.py`. Интерфейс не участвует в распознавании.

## Как вызывается

```python
from language.lexer import Lexer
from language.parser import Parser

lexical = Lexer().analyze(source)
syntax = Parser().analyze(lexical)
if syntax.ok:
    print("Синтаксис верен")
else:
    error = syntax.diagnostics[0]
    print(error.line, error.column, error.message)
```

Лексер создаёт цепочку пар `(таблица, индекс)` и позиции в тексте.
Парсер использует именно пары: EQ распознаёт терминал, ID — TI=3,
NUM — TN=4. gl передвигает указатель на следующую лексему.
Символьные правила Id и Nb уже проверены лексером: нет повторной проверки букв,
цифр, систем счисления и перевода чисел. Это соответствует входу примера из
методички: числовому представлению лексем.

## Эквивалентное устранение левой рекурсии

В таблице фигурные скобки означают повторение ноль или более раз;
квадратные скобки в записи `[ St ... ]` — терминалы модельного языка.

| Исходные продукции | Реализация процедурой |
| --- | --- |
| Pr → StL end | StL(); EQ/end; конец входа |
| StL → Dc Sep \| St Sep \| StL Dc Sep \| StL St Sep | Один или более `(Dc или St), Sep` в цикле |
| IdL → Id \| IdL , Id | Id(); затем `{ , Id }` |
| Cmp → [ St CmpL ] | `[`, St(), CmpL(), `]` |
| CmpL → ε \| CmpL Sep St | `{ Sep St }` |
| ExL → Ex \| ExL , Ex | Ex(); затем `{ , Ex }` |
| Ex → Op \| Ex Rel Op | Op(); затем `{ Rel Op }` |
| Op → Sl \| Op Add Sl | Sl(); затем `{ Add Sl }` |
| Sl → Mn \| Sl Mul Mn | Mn(); затем `{ Mul Mn }` |

Остальные процедуры непосредственно повторяют правые части соответствующих
правил. Например ForSt вызывает Asg, проверяет `to`, вызывает Ex, при наличии
`step` вызывает ещё один Ex, затем St и проверяет `next`.
Mn вызывает себя для `! Mn`, а для `( Ex )` вызывает Ex и проверяет `)`.

Циклы сохраняют язык исходной грамматики и устраняют бесконечные вызовы
при левой рекурсии. Вложенные конструкции по-прежнему разбираются рекурсивно.
Соглашение для неоднозначного else: ближайший незавершённый if.

## Существенные границы грамматики

- Pr содержит хотя бы одну конструкцию, а не только end.
- Sep требуется после каждой конструкции верхнего уровня, включая последнюю.
- В Cmp разрешены только St; Dc внутрь блока не входит.
- В Cmp разделитель стоит между операторами, а не после последнего оператора.
- Перевод строки — самостоятельный Sep: нельзя произвольно пропускать пустые строки.
- После end не должно быть лексем, включая перевод строки. В контрольных
  файлах нет завершающего перевода после end; это намеренно, по формальной грамматике.
- Для условного и while обязательны круглые скобки; отдельного Sep перед телом нет.
- Перед else также нет Sep. Если нужен блок, тело записывается через `[ ... ]`.
- readln принимает IdL, writeln — ExL. `readln(x)` не соответствует грамматике.
- Унарная операция только `!`; отрицательное число записывается выражением `0 - 1`.
- Несколько отношений подряд разрешены правилом Ex, независимо от будущей семантики.

Ошибка указывает на первую лексему, не подходящую в текущей процедуре.
Если пропущен символ, выделяется следующая полученная лексема; в конце файла
указывается позиция EOF. После первой ошибки анализ останавливается.
Для слишком глубокой вложенности выдаётся отдельный предел реализации.

## Контрольные примеры

Через меню «Примеры» доступны 10 корректных программ и 47 программ с ошибками.
В `examples/syntax/cases.json` каждому файлу сопоставлены результат,
описание нарушения и процедура, которая должна обнаружить ошибку.

Группы нарушений: структура программы, объявления, присваивание и выражения,
составные операторы, условия, циклы, ввод и вывод. Это представители классов
синтаксических ошибок, а не перечисление всех ошибочных текстов, которых бесконечно много.
Все 47 ошибочных примеров лексически корректны: проверяется именно синтаксис.

Независимая проверка в `tests/test_parser.py`: алгоритм Эрли принимает исходные
леворекурсивные продукции, а не процедурный алгоритм рабочего парсера.
Сравниваются контрольные программы, случайные выражения и мутации терминалов.
Дополнительно проверены координаты диагностики, повторное использование Parser,
большие списки и запрет запуска после лексической ошибки.

Семантика не проверяется: например, использование необъявленного имени или
смешение типов само по себе не означает синтаксическую ошибку.
