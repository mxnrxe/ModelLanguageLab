# Model Studio

Редактор модельного языка с лексическим анализом на Python 3.10+ и интерфейсом Tkinter.
Сторонние библиотеки не нужны. Лексический анализ реализован вручную;
генераторы анализаторов и регулярные выражения для распознавания не используются.

## Запуск

Откройте папку `ModelLanguageLab` в PyCharm, выберите интерпретатор
`.venv\Scripts\python.exe` и запустите `main.py`.
Также можно открыть `Запустить.cmd` двойным щелчком.

В интерфейсе: F5 — лексический анализ; Ctrl+N — новый файл; Ctrl+O — открыть; Ctrl+S — сохранить;
Ctrl+Shift+S — сохранить как. «Примеры» содержит пять программ.
Файлы сохраняются в UTF-8; читаются UTF-8, UTF-8 BOM, UTF-16 BOM и CP1251.
Выбор лексемы показывает её в тексте. Выбор записи TI/TN подсвечивает все её
вхождения. Экспорт JSON включает таблицы, лексемы, диагностику и журнал дуг;
экспорт TXT содержит цепочку пар. При ошибке выводится корректный префикс цепочки.

## Перенос на другое устройство

```text
git clone https://github.com/mxnrxe/ModelLanguageLab.git
cd ModelLanguageLab
python -m venv .venv
```

В Windows:

```text
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe main.py
```

В macOS/Linux:

```text
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python main.py
```

Нужны Python 3.10+ и Tkinter. Пакеты из pip не требуются.
Для приватного репозитория нужен доступ к аккаунту владельца.
На Linux пакет Tkinter может устанавливаться отдельно средствами системы.

## Соответствие итоговой схеме

Зафиксированная схема находится в `docs/Схема.drawio`, SHA256 — в `docs/source_sha256.txt`.
Это копия итогового `LR2_итоговая.drawio`, геометрия и логика которого при переписывании кода не менялись.

`language/lexer.py` содержит явные ветви `if/elif` для состояний H, I, KW, N2, P2, N16,
P16, N8, N10, U10, P8, Exp, TT, Mn, T, E1, EX, E2, E3, E4, PP, NK, C, DV, CM, CB, OP.
START — начальная дуга; KW/OP — ромбы z != 0; V/ER — завершение.
Метод `analyze` повторяет `scanner` до V/ER. `scanner` выполняет одну дугу.
У каждой ветви указан ID исходной дуги; журнал показывает те же ID и действия.
Копии кружков одного имени — одно состояние, действия входа выполняются один раз.

В рабочем анализаторе нет перебора таблицы переходов и диспетчера действий.
`language/transitions.py` содержит 117 переходов только для проверок соответствия XML.
Проверочный интерпретатор `tests/xml_oracle.py` отделён от программы и исполняет XML независимо.
CH меняется только в `gc`; ветви без gc сохраняют текущий символ.
При завершении числа ограничитель остаётся для H.

TW=1, TL=2, TI=3, TN=4. Индексы начинаются с 1, при отсутствии в look z=0.
Ключ TN — точное числовое значение: 1, 01, 1D, 1B, 1O, 1H, 1.0, 1E0
ссылаются на одну запись. Написания и виды сохраняются.
Буфер B содержит строку числа; `put(4, kind)` переводит её вручную через accumulate
и Fraction, без float, regex и готового генератора лексеров.
В реализации сохранены предел масштаба 10000 и журнал до 100000 дуг.
Превышение масштаба отмечается как предел реализации, ограничение журнала не прекращает анализ.

Листинг: `docs/scanner_if_elif_для_отчёта.txt`.
Соответствие кружков строкам кода: `docs/Соответствие_схемы_и_if_elif.txt`.
Назначение функций: `docs/Функции_if_elif.txt`.
Полный самостоятельный код: `docs/Лексический_анализатор_для_отчёта.py`.

## Расширение

`language/models.py` — данные Token, Diagnostic, AnalysisResult, NumberEntry.
Следующий синтаксический анализатор может принимать `AnalysisResult.tokens`;
исходные позиции и виды числовых вхождений уже доступны для диагностики и
проверки типов. `ui/` отвечает за редактор и представление результатов.
Сейчас программа выполняет только лексический анализ: баланс скобок,
конструкции операторов, типы и выполнение относятся к следующим лабораторным.

## Проверка

```text
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tests\smoke_ui.py
```

17 тестов включают все 117 дуг XML и 14504 проверки одного перехода
(28 состояний, 259 классов символов, оба результата z=0/z!=0).
Дополнительно 4230 полных входов сравниваются с отдельным интерпретатором итогового XML:
пары, координаты, буферы, TI/TN, диагностика и журнал совпали, расхождений нет.
Проверены неоднозначные числовые записи, все таблицы, ошибочные продолжения,
комментарии, переносы строк, ограничения ресурсов и интеграция Tkinter.
Отчёт проверки: `docs/validation.json`.
