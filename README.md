# Model Studio

Редактор модельного языка с лексическим и синтаксическим анализом на Python 3.10+ и интерфейсом Tkinter.
Сторонние библиотеки не нужны. Лексический анализ реализован вручную;
генераторы анализаторов и регулярные выражения для распознавания не используются.

## Запуск

Откройте папку `ModelLanguageLab` в PyCharm, выберите интерпретатор
`.venv\Scripts\python.exe` и запустите `main.py`.
Также можно открыть `Запустить.cmd` двойным щелчком.

В интерфейсе: F5 — лексический анализ; F6 — синтаксический анализ;
Ctrl+N — новый файл; Ctrl+O — открыть; Ctrl+S — сохранить;
Ctrl+Shift+S — сохранить как. «Примеры» содержит лексические примеры и контрольные
программы для синтаксиса, сгруппированные по конструкциям.
Файлы сохраняются в UTF-8; читаются UTF-8, UTF-8 BOM, UTF-16 BOM и CP1251.
Выбор лексемы показывает её в тексте. Выбор записи TI/TN подсвечивает все её
вхождения. Экспорт JSON включает таблицы, лексемы, диагностику и журнал дуг;
экспорт TXT содержит цепочку пар. При ошибке выводится корректный префикс цепочки.

## Перенос на другое устройство

```text
git clone https://github.com/mxnrxe/ModelLanguageLab.git
cd ModelLanguageLab
python -m venv .venv
```

В Windows:

```text
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe main.py
```

В macOS/Linux:

```text
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python main.py
```

Нужны Python 3.10+ и Tkinter. Пакеты из pip не требуются.
Для приватного репозитория нужен доступ к аккаунту владельца.
На Linux пакет Tkinter может устанавливаться отдельно средствами системы.

## Соответствие итоговой схеме

Зафиксированная схема находится в `docs/Схема.drawio`, SHA256 — в `docs/source_sha256.txt`.
Это копия итогового `LR2_итоговая.drawio`, геометрия и логика которого при переписывании кода не менялись.

`language/lexer.py` содержит явные ветви `if/elif` для состояний H, I, KW, N2, P2, N16,
P16, N8, N10, U10, P8, Exp, TT, Mn, T, E1, EX, E2, E3, E4, PP, NK, C, DV, CM, CB, OP.
START — начальная дуга; KW/OP — ромбы z != 0; V/ER — завершение.
Метод `analyze` повторяет `scanner` до V/ER. `scanner` выполняет одну дугу.
У каждой ветви указан ID исходной дуги; журнал показывает те же ID и действия.
Копии кружков одного имени — одно состояние, действия входа выполняются один раз.

В рабочем анализаторе нет перебора таблицы переходов и диспетчера действий.
`language/transitions.py` содержит 117 переходов только для проверок соответствия XML.
Проверочный интерпретатор `tests/xml_oracle.py` отделён от программы и исполняет XML независимо.
CH меняется только в `gc`; ветви без gc сохраняют текущий символ.
При завершении числа ограничитель остаётся для H.

TW=1, TL=2, TI=3, TN=4. Индексы начинаются с 1, при отсутствии в look z=0.
Ключ TN — точное числовое значение: 1, 01, 1D, 1B, 1O, 1H, 1.0, 1E0
ссылаются на одну запись. Написания и виды сохраняются.
Буфер B содержит строку числа; `put(4, kind)` переводит её вручную через accumulate
и Fraction, без float, regex и готового генератора лексеров.
В реализации сохранены предел масштаба 10000 и журнал до 100000 дуг.
Превышение масштаба отмечается как предел реализации, ограничение журнала не прекращает анализ.

Листинг: `docs/scanner_if_elif_для_отчёта.txt`.
Соответствие кружков строкам кода: `docs/Соответствие_схемы_и_if_elif.txt`.
Назначение функций: `docs/Функции_if_elif.txt`.
Полный самостоятельный код: `docs/Лексический_анализатор_для_отчёта.py`.

## Синтаксический анализ

Вкладки анализа используют один редактор, подсветку и файл. F6/F7/F8 запускают
один общий рекурсивный спуск: синтаксис, семантические действия и ПОЛИЗ.
После лексического анализа отдельного предварительного синтаксического прохода нет.
При первой ошибке показываются строка,
столбец, конструкция, ожидаемые символы и фактическая лексема. Кнопка перехода
выделяет место в редакторе. После редактирования результат нужно обновить.

Экспорт на синтаксической вкладке сохраняет заключение и диагностику (JSON/TXT).
На лексической вкладке сохраняется прежний формат таблиц и цепочки.

`language/parser.py` содержит методы Pr, StL, Sep, Dc, IdL, Tp, St, Cmp, CmpL,
Asg, Cond, ForSt, WhileSt, ExL, Ex, Rel, Op, Add, Sl, Mul, Mn, Lg, Id, Nb.
Это ручной рекурсивный спуск: каждому синтаксическому нетерминалу соответствует
метод; левая рекурсия списков и выражений устранена эквивалентными циклами.
LEX — текущая лексема; gl читает следующую; EQ сравнивает числовые пары таблиц,
ID и NUM определяют категории лексем. Исходные символы повторно не распознаются.

Грамматика соблюдается буквально: Sep — `:` или настоящий перевод строки
(в интерфейсе `/n`), в том числе перед `end`. Нет пустых конструкций, пустого
блока, произвольных пустых строк и разделителя перед `]`. Последняя лексема —
`end`, поэтому перевод строки после него считается лишним. Пробелы и закрытые
комментарии после `end` не создают лексем и допустимы.
`else` относится к ближайшему незавершённому `if`. Цепочки отношений разрешены
продукцией `Ex → Ex Rel Op`; унарного минуса в грамматике нет.

Дерево в программе не строится. В ЛР5 интерфейс запускает общий проход,
включающий синтаксис, проверку объявлений и типов и генерацию ПОЛИЗ.
Самостоятельный Parser остаётся доступен для проверки одной грамматики в тестах.
Защита от переполнения стека: 80 одновременно вложенных вызовов St/Mn;
превышение отмечается как предел реализации, а не доказательство ошибки грамматики.
Длинные списки, последовательности и цепочки операций обрабатываются циклами.

Обоснование преобразований: [docs/ЛР3_Рекурсивный_спуск.md](docs/ЛР3_Рекурсивный_спуск.md).
Контрольные файлы: `examples/syntax/valid/` (10 программ),
`examples/syntax/invalid/` (47 программ). В `examples/syntax/cases.json`
записаны ожидаемые результаты и места ошибки по нетерминалам.

## Расширение

ЛР4: F7 открывает семантические результаты общего прохода.
На вкладке «Семантика» доступны TI с типами, таблица TOP и стек выражений;
результат можно экспортировать в JSON. Пример — «ЛР4 — семантика и стек».
Правила и ограничения описаны в [docs/ЛР4_Семантика.md](docs/ЛР4_Семантика.md).

ЛР5: F8 показывает ПОЛИЗ, F9 выполняет успешно переведённую программу.
Ввод для readln задаётся значениями через пробел в поле над ПОЛИЗ.
Числовой вывод округляется до 12 знаков после точки, без лишних нулей;
внутри вычисления остаются точными (Fraction).
Вкладка показывает команды с парами таблиц, вывод и ход исполнения.
Объявленные переменные получают адреса. При чтении переменной без значения,
делении на ноль, нулевом шаге for и нехватке/ошибке входа выводится ошибка выполнения.
Предел - 100000 команд, журнал - 3000 шагов, размер числового операнда - 16384 бит.
В for начальное значение, граница и шаг вычисляются при входе, граница включена;
положительный шаг увеличивает счётчик, отрицательный уменьшает. Логические
операции вычисляют оба операнда. Семантика и стек описаны в docs/ЛР5_ПОЛИЗ.md.

`language/models.py` — данные Token, Diagnostic, AnalysisResult, NumberEntry.
`language/parser.py` принимает `AnalysisResult` с токенами и позициями;
возвращает `SyntaxResult`, не зависящий от Tkinter. Исходные позиции и виды
числовых вхождений доступны для будущей проверки типов. `ui/` отвечает
за редактор и представление результатов; `ui/syntax_panel.py` — за синтаксическую вкладку.

## Проверка

```text
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tests\smoke_ui.py
.venv\Scripts\python.exe tests\smoke_syntax_ui.py
.venv\Scripts\python.exe tests\smoke_poliz_ui.py
```

Проверки лексера включают все 117 дуг XML и 14504 проверки одного перехода
(28 состояний, 259 классов символов, оба результата z=0/z!=0).
Дополнительно 4230 полных входов сравниваются с отдельным интерпретатором итогового XML:
пары, координаты, буферы, TI/TN, диагностика и журнал совпали, расхождений нет.
Проверены неоднозначные числовые записи, все таблицы, ошибочные продолжения,
комментарии, переносы строк, ограничения ресурсов и интеграция Tkinter.
Отчёт проверки: `docs/validation.json`.

Проверки парсера включают контрольные файлы, координаты ошибок, блокировку
при лексической ошибке, ограничения вложенности и длинные списки.
Независимый тестовый алгоритм Эрли сравнивает принятие программ с исходными
леворекурсивными продукциями ЛР1, включая пустую продукцию CmpL.
Он проверяет контрольные программы, случайные выражения и мутации терминалов.
Оба smoke-теста открывают настоящее окно Tkinter и проверяют работу интерфейса.
